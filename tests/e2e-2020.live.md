## Live E2E Test for 2020

This guide explains how to run the live end‑to‑end test that exercises the full tournament flow for year 2020 against your Google Cloud Firestore database. The test only affects data for year 2020 and deletes any temporary data it creates.

### What this test does

- Creates a small tournament bracket for year `2020` using `createNewBracket`.
- Updates teams in that bracket using `updateBracket` (simulates team/seed changes).
- Marks winners for two games via `updateTeamRecords`, then undoes one via `undoTeamRecords`.
- Creates an entry for the 2020 tournament via `createNewEntry`, updates that entry, and runs `updatePossiblePoints` to recalculate totals.
- Verifies that the undo worked, that the entry update persisted, and that points fields are present.
- Cleans up all temporary data at the end:
  - Deletes the created entry
  - Deletes all `2020` rows from `games` and `schoolRecord`

Relevant source files:
- `tests/e2e-2020.live.test.js`
- `src/services/tourneyService.js`
- `src/services/gameService.js`
- `src/services/viewService.js`
- `src/services/pointsService.js`
- `src/repositories/repository.js`

### Safety and scope

- The test is DISABLED by default and only runs when `LIVE_E2E=true` is set.
- It operates exclusively on year `2020`. No other years are modified.
- It performs a pre‑clean and post‑clean to ensure a predictable state and remove temporary data.

### Prerequisites

- Google Cloud credentials set up in your environment (e.g., `GOOGLE_APPLICATION_CREDENTIALS` or Workload Identity on GCP).
- The dataset configured in `src/config/app.js` (`datasetId`) accessible to your credentials.
- Node dependencies installed.

### How to run

Run only this test file with the live flag enabled and Node's VM modules support:

```bash
npm run test:live-e2e
```

Expected behavior:
- If `LIVE_E2E` is not set to `true`, the test is skipped.
- When enabled, it creates and manipulates 2020 data and then removes it.

### Data created (and removed)

- `games` (year = 2020): a small bracket subset is inserted and then deleted.
- `schoolRecord` (year = 2020): seed/region records for the small bracket subset are inserted and then deleted.
- `entry` (year = 2020): a temporary entry with group `E2E-Temp-2020`, email `e2e2020@example.com`, team name `E2E Team 2020` is created, updated, then deleted.

### Troubleshooting

- If the test fails mid‑run and leaves residue, re‑run the test; the pre‑clean step will remove leftover 2020 rows it recognizes.
- Ensure your Google Cloud credentials have read/write permissions on the configured collections: `games`, `schoolRecord`, `entry`, `groups`.
- If your dataset/table names differ, update `datasetId` in `src/config/app.js` accordingly.

### Notes

- The bracket is intentionally minimal to limit the footprint while still exercising the full workflow.
- The test uses real service/repository layers to mirror production behavior.
